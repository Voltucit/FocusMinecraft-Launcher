# 玩家界面与安装状态同步整改

日期：2026-10-24。依赖保持 FocusMinecraftCore 1.0.1、WPF-UI 4.3.0、.NET 10。没有核心迁移、SDK 升级或版本元数据重写。

## 实际问题与修复

原下载命令仅等待安装并保存版本 ID，主页和版本页各自持有本地列表，完成后没有统一重新查询；缓存页面也不会因重新导航而更新。

现在 LauncherServices 只创建一份 InstanceCatalog。DownloadsViewModel 等待 InstallationAdapter 的真正成功返回，取得 SDK 返回的版本 ID，携带提交时的游戏根目录及操作 ID 调用 InstallationSucceededAsync。百分比达到 100% 不触发完成。失败或取消不调用完成入口。安装成功后即使刷新失败，仍明确区分“安装完成、列表更新失败”，不误报安装失败。

InstanceCatalog 通过既有 VersionAdapter / SDK 重新枚举本地版本。查询和集合发布整体串行；集合更新、选择及通知在 Dispatcher 执行；根目录及切换代次校验防止旧结果覆盖新目录。操作 ID 去重只保留最近 256 个。每个请求均保留查询发布机会，不因后续被取消请求而丢弃先前成功安装的刷新。

Home 与 Versions 绑定同一只读可观察集合，主页当前版本来自同一选择。Downloads 根据该集合更新已安装标记，分类和所选下载版本保留。集合按 SDK 快照增量替换、移动，沿用元数据相同的展示对象，避免清空重建和重复项。SDK 元数据错误仍保留，仅在普通页面显示中文提示，原错误码可在折叠的高级诊断中查看。

当前策略：已有选中版本仍有效时保留；没有有效选择时选本次安装版本或列表首项。切换根目录重新查询，不移动游戏文件。所有工作目录继续是 versions/<版本>。OperationService 仍是原有串行文件任务系统，没有新增并行 Minecraft 安装队列。

## 界面与账户

主页突出当前账号、游戏版本和启动按钮。头像 / 名称打开窗口内部的账户侧面板，点击账号行使用并关闭；添加正版 / 离线、删除和设默认仍调用原 AccountManager。当前账号与面板预览候选分开，选中候选不会悄悄改变启动身份。

主页不再堆放校验、修复和日志按钮，它们集中在“更多 → 诊断日志”。Minecraft 资讯入口打开官网真实资讯页面，没有伪造新闻列表或更新公告。图形为中性功能标识，不冒充玩家皮肤或整合包封面。游戏设置仍为全局设置，页面已说明适用全部版本。

普通设置仅保留游戏目录、Java、内存、窗口、主题和壁纸等已有能力。JVM 参数和缺失元数据时的 Java 要求归入高级参数；自定义壁纸 API 继续是可选高级功能。控件样式继承 WPF-UI 的原模板，避免覆盖隐式样式后回退为系统旧模板；页面内容容器不再主动获得焦点形成大面积焦点框。固定窗口、内部导航和缓存页面保持。

离线改名因 SDK 无公开接口已询问并获准暂缓，见 agent.md / FEATURE_GAPS.md。

## 开发者配置

见 DEVELOPER_SERVICES.md。用户设置中的旧 MicrosoftClientId 仅保留兼容，不再被认证读取；旧 CurseForge 加密文件不删除、不读取。没有新的用户凭据迁移或自动认证。

## 状态、错误与日志

PlayerText 将安装和认证阶段、LaunchState 及分类启动错误转换为玩家中文提示；离线类型不显示 Offline、UUID 或资格布尔值。FailureText 保留登录、无游戏资格、目录权限、Java、版本及文件错误的区别。

DiagnosticLog 仅记录固定操作名、异常类型 / HResult 或 SDK 结构化错误代码，不记录异常正文、参数、请求 URL 和 Token。GameHost 在准备失败或退出后均尝试导出 SDK 已脱敏日志，导出失败不改变真实启动结果。用户分享游戏原始输出前仍需自行检查。

## 范围与验证

没有新增底层解析、整包安装、Mod 写入、独立实例或图标缓存系统；未触及用户游戏和账号数据。在线 / 本地整包安装入口仍因目录冲突暂缓，未来合法接入时必须在 SDK 真正成功后调用同一完成入口。

仅开发、编译与发布，实际 UI、登录、游戏下载和游戏运行均未验证。操作步骤见 MANUAL_TESTING.md，实际构建结果见 BUILD_RESULTS.md。
